KATEGORI 1: ALGORITMA & MODEL
----------------------------------------------------------------------

Q1: Mengapa memilih Decision Tree bukan algoritma lain seperti SVM atau Neural Network?
A1: Decision Tree dipilih karena:
    a) White-box model — aturan keputusan transparan, mudah dipahami tenaga medis
    b) Tidak memerlukan normalisasi data
    c) Dapat menangani data numerik dan kategorikal
    d) Menghasilkan decision path yang bisa dijelaskan ke dokter
    e) Sesuai kebutuhan SPK yang harus bisa dipertanggungjawabkan

Q2: Apa itu entropy dan Information Gain?
A2: Entropy mengukur ketidakpastian/impurity dalam suatu node.
    Information Gain = pengurangan entropy setelah split.
    Decision Tree memilih fitur yang memberikan Information Gain tertinggi.
    Rumus: Entropy(S) = -p1*log2(p1) - p2*log2(p2)

Q3: Mengapa class_weight='balanced' digunakan?
A3: Karena dataset tidak seimbang (12.7% risiko vs 87.3% normal).
    Tanpa balanced, model akan bias ke kelas mayoritas.
    Balanced memberikan bobot lebih tinggi pada kelas minoritas (risiko).

Q4: Precision rendah (24.25%) — bagaimana menjelaskannya?
A4: Precision rendah adalah konsekuensi dari:
    a) class_weight=balanced yang membuat model agresif mendeteksi risiko
    b) Dalam konteks deteksi dini, lebih baik False Positive tinggi
       daripada False Negative tinggi (melewatkan pasien berisiko)
    c) Recall 79.83% menunjukkan ~80% pasien berisiko terdeteksi

Q5: Apakah model ini overfitting?
A5: Tidak. Gap antara training accuracy dan testing accuracy hanya 0.002.
    Cross-validation 10-fold juga menunjukkan F1 std ±0.009 yang stabil.

Q6: Mengapa Gradient Boosting recall-nya sangat rendah (7.53%)?
A6: Gradient Boosting cenderung konservatif tanpa class_weight=balanced.
    Model ini memprediksi hampir semua pasien sebagai "tidak risiko"
    sehingga accuracy tinggi (87.19%) tapi recall sangat rendah.

KATEGORI 2: DATASET & PREPROCESSING
----------------------------------------------------------------------

Q7: Dari mana dataset berasal?
A7: Dataset berasal dari rekam medis pasien RSU Aulia, Jagakarsa,
    Jakarta Selatan. Total awal 31.638 rekord.

Q8: Bagaimana proses data cleaning?
A8: a) Drop 19 kolom kosong
    b) Parse usia dari teks (contoh: "55 tahun 3 bulan") ke numerik
    c) Split "130/85" menjadi sistolik=130, diastolik=85
    d) Ekstrak keluhan sesak dada dari teks bebas
    e) Hapus baris dengan BMI=0, TD=0/0, BMI>100000
    f) Label target dari ICD-10 kode I10-I79

Q9: Bagaimana menentukan label risiko_jantung?
A9: Label ditentukan berdasarkan kode ICD-10 pada kolom diagnosa:
    I10-I79 = Penyakit kardiovaskular → risiko_jantung = 1
    Selain itu → risiko_jantung = 0

Q10: Apakah ada missing values di dataset bersih?
A10: Tidak. Setelah preprocessing, semua 27.817 rekord lengkap tanpa
     missing values.

Q11: Mengapa kadar kolesterol tidak dimasukkan?
A11: Data kolesterol tidak tersedia di dataset asli RSU Aulia.
     Sebagai gantinya, keluhanawal_sesak_dada digunakan karena
     memiliki korelasi klinis kuat dengan penyakit jantung.

KATEGORI 3: SISTEM & IMPLEMENTASI
----------------------------------------------------------------------

Q12: Jelaskan arsitektur sistem CARDIOCARE.
A12: Arsitektur client-server:
     Frontend (HTML/CSS/JS) → REST API (Flask) → Dataset CSV + Model
     Client-side: model.js untuk prediksi di browser
     Server-side: decision_tree_model.pkl untuk prediksi di server

Q13: Mengapa menggunakan Flask?
A13: Flask dipilih karena:
     a) Lightweight — cocok untuk prototype dan demo
     b) Python native — mudah integrasi dengan scikit-learn
     c) REST API sederhana — cukup JSON response
     d) Mudah di-deploy

Q14: Apakah data yang ditampilkan benar-benar data riil?
A14: Ya, 100% data riil dari dataset_cleaned.csv (27.817 pasien).
     Tidak ada data dummy atau hardcoded. Semua halaman mengambil
     data dari API Flask.

Q15: Bagaimana cara kerja prediksi client-side?
A15: Model Decision Tree diekspor ke format JavaScript (model.js).
     Struktur pohon direpresentasikan sebagai nested object.
     Browser melakukan traversal dari root ke leaf berdasarkan
     input user, tanpa perlu request ke server.

Q16: Apa itu decision path dan mengapa penting?
A16: Decision path adalah alur keputusan yang dilalui model dari
     root node ke leaf node. Contoh:
     "Usia > 38.33 → Sistolik > 124.5 → BMI > 26.38 → RISIKO"
     Penting karena memberikan transparansi kepada dokter tentang
     MENGAPA pasien diklasifikasikan berisiko.

KATEGORI 4: EVALUASI & VALIDASI
----------------------------------------------------------------------

Q17: Apa itu ROC-AUC dan bagaimana interpretasinya?
A17: ROC-AUC mengukur kemampuan model membedakan kelas positif dan
     negatif. Nilai 0.5 = random, 1.0 = sempurna.
     AUC = 0.7927 berarti model memiliki discriminative power yang
     baik (di atas 0.7).

Q18: Jelaskan confusion matrix model Anda.
A18: TN=2.878 (benar normal), FP=1.979 (salah deteksi risiko),
     FN=143 (melewatkan risiko), TP=564 (benar deteksi risiko).
     FN rendah (143) menunjukkan model baik dalam mendeteksi
     pasien berisiko.

Q19: Apa itu cross-validation dan mengapa digunakan?
A19: Cross-validation membagi data menjadi k fold, lalu melatih model
     k kali dengan fold berbeda sebagai test set. Digunakan untuk:
     a) Memastikan model stabil (tidak tergantung split tertentu)
     b) Estimasi performa yang lebih robust
     c) Hasil: F1 std ±0.009 (sangat stabil)

Q20: Bagaimana membandingkan dengan penelitian lain?
A20: Beberapa penelitian DT untuk penyakit jantung:
     - Antika et al. (2023): Accuracy tinggi pada klasifikasi jantung
     - Karima (2025): ML membantu prediksi risiko
     Model kami: Recall 79.83% dengan data riil RS Indonesia.

KATEGORI 7: SKENARIO & DEMO
----------------------------------------------------------------------

Q27: Bisakah mendemonstrasikan prediksi langsung?
A27: Ya. Input contoh: Usia=60, Gender=L, BMI=30, TD=160/95, Sesak=Ya
     → Model memprediksi RISIKO JANTUNG dengan probabilitas tertentu.
     Decision path menunjukkan alur keputusan step by step.

Q28: Apa yang terjadi jika input tidak valid?
A28: Frontend melakukan validasi:
     - Usia: 0-120
     - BMI: 1-100
     - Sistolik: 50-300
     - Diastolik: 30-200
     Alert muncul jika input di luar rentang.

Q29: Apakah bisa export data pasien?
A29: Ya, tersedia 3 format:
     - CSV: langsung download dari /api/export/csv
     - Excel: generate XLS dari data API
     - PDF: print-ready report dengan statistik lengkap

Q30: Bagaimana jika server Flask tidak berjalan?
A30: Frontend memiliki fallback mode:
     - Dashboard: charts dummy
     - Prediksi: model.js client-side tetap berfungsi
     - Data pasien: 5 sample statis
     Namun untuk skripsi/demo, server harus berjalan.
